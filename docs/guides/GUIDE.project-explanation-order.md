# 프로젝트 설명 순서 가이드

## 위치

`admin-boiler-plate` 루트 기준 전체 구조

## 목적

현재 만들어진 프로젝트를 설명할 때, 듣는 사람이 빠르게 이해할 수 있도록 발표/문서 설명 순서를 표준화합니다.

## 설명 순서

1. 한 줄 소개

- 프로젝트가 무엇을 해결하는지 한 문장으로 시작합니다.
- 예: "관리자 페이지 보일러플레이트로, 인증/라우팅/공통 UI를 빠르게 재사용할 수 있도록 구성했습니다."

2. 대상 사용자와 핵심 시나리오

- 누가 사용하는지(운영자, 관리자 등), 어떤 작업을 하는지 먼저 설명합니다.
- 핵심 흐름 2~3개만 고릅니다. (로그인, 목록 조회, 상세/수정)

3. 기술 스택과 선택 이유

- `React + Vite`, 상태관리, 스타일 방식, API 계층을 짧게 소개합니다.
- "무엇을 썼는지"보다 "왜 썼는지"를 한 줄씩 붙입니다.

4. 폴더 구조 개요

- `src/pages`, `src/components`, `src/store`, `src/api`, `src/routes` 중심으로 설명합니다.
- 세부 파일을 모두 나열하지 말고 책임 단위로 묶어 설명합니다.

5. 라우팅/권한 흐름

- `routes/router.jsx`, `PrivateRoute.jsx`, `routes/paths.js`를 기준으로 진입 흐름을 설명합니다.
- 비로그인/권한 없음/정상 접근 케이스를 분리해서 말합니다.
- 컴포넌트 데모는 중첩 라우트로 분리되어 있습니다: `/components/table`, `/components/modal`, `/components/etc`.
- 헤더 버튼(`src/components/Header/Header.jsx`)은 각 데모 라우트로 직접 이동합니다.

6. 상태관리 구조

- 전역 상태(`store`)와 화면 로컬 상태의 경계를 설명합니다.
- 예: 모달/컨펌/유저 상태는 store에서, 토스트는 `src/utils/toast.js`의 `showToast`로 관리된다고 설명합니다.

7. API 통신 구조

- `api/axios.js`와 도메인 API(`users.api.js` 등)의 역할을 나눠 설명합니다.
- 요청-응답-에러 처리 기준을 간단히 덧붙입니다.

8. 공통 컴포넌트 재사용 전략

- `Button`, `Modal`, `Table`, `Toast` 같은 공통 컴포넌트 설계 원칙을 설명합니다.
- "props로 확장 가능한 구조"처럼 팀이 가져갈 규칙을 강조합니다.
- MobX 페이지 컴포넌트는 `const Component = () => {}` 후 `const ObservedComponent = observer(Component)`로 래핑하는 패턴을 사용해 Fast Refresh 안정성을 높입니다.

9. 대표 화면 데모

- 실제로 한 페이지(예: 사용자 목록)를 열어 데이터 조회, 액션 버튼, 모달 호출 흐름을 보여줍니다.
- 코드 설명은 "페이지 -> 컴포넌트 -> store/API" 순서로 따라갑니다.

10. 마무리: 한계와 다음 확장 포인트

- 현재 범위(예: 기본 관리자 기능)와 미구현 항목을 명확히 말합니다.
- 다음 단계(권한 세분화, 테스트, 공통 폼 고도화 등)를 제시합니다.

## 5분 요약용 압축 순서

1. 한 줄 소개
2. 폴더 구조 5개(`pages/components/store/api/routes`)
3. 로그인/권한 라우팅 흐름
4. 대표 화면 1개 데모
5. 확장 포인트 2개

## 설명 체크리스트

- 기술 설명 전에 "문제/사용자"를 먼저 말했다.
- 코드 파일명보다 "역할" 중심으로 설명했다.
- 라우팅, 상태, API, UI 재사용 흐름이 하나로 연결되게 설명했다.
- 마지막에 확장 계획을 제시했다.
